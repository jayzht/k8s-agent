## 二、三种写法（按篇幅选）

### 版本 A：一行版（技能栏 / 项目列表）

> **K8s 运维 Agent**（Python）：从零实现「只读自动执行 + 写操作强制人工审批」的
> Agent 执行架构，含提示注入防御与 15 剧本确定性评测。15 只读 / 10 写工具，
> 284 条测试。`github.com/jayzht/k8s-agent`

### 版本 B：标准版（4 条，最常用）⭐

**K8s 运维 Agent —— 对话式集群诊断与受控变更**　｜　个人项目　｜　2026.09

- **结构性读写切分（核心设计）**：工具表静态声明 15 个只读 + 10 个写；**未登记的
  工具一律判定为写操作并拒绝**（fail closed）。写路径必须携带与方案绑定的批准凭据
  （批准 A 无法执行 B），执行前**重跑一次服务端 dry-run** 防止审批期间的集群漂移，
  叠加命名空间白名单、方案 TTL 与哈希链审计。
- **提示注入防御**：把集群里读到的日志/事件当作**不可信输入**——围栏标注 + 加权
  信号计分，**只标注不删改原文**（清洗掉等于销毁证据）；命中即发事件、写审计、
  控制台弹红色告警卡。**调研 8 个同类开源项目后确认：无一个实现该能力。**
- **工具层可拔插**：`Provider` 协议 + 注册表，**构造时拒绝缺少 dry-run 契约的写工具**
  （扩展能力不削弱安全边界）；自带只读 Prometheus / Loki；实现 **MCP 双向**——
  既是 MCP server（只借出只读能力），也是 MCP client（把外部工具接进来，
  **对端自称只读不算数，必须人工点名**）；支持在 **Web 页面上直接添加外部工具**并热生效。
- **评测驱动的迭代（最有含金量的一块）**：15 个真故障剧本、真集群真模型、
  **确定性判据（不用 LLM 当裁判）**。先重复采样把"抽样波动"和"可复现缺陷"分开，
  再逐个定位并修复，**把 10~11/15 提到 14/15（93%）**——且每一步都有前后对照的
  评测数据（`docs/eval-report.md`，九轮完整记录）。284 条测试 + 31 项前端端到端；
  容器化交付（Docker + Compose + 一条命令从零建集群）；`doctor` 自检逐项检查
  RBAC / metrics-server / 模型配置，每项失败给可粘贴的修复命令。

### 版本 C：技术详版（投平台 / AI 应用，可拆两段）

**第一段：安全执行架构**

- **两条执行路径在代码层面分开**：`run_readonly()` 主动拒绝写工具（取证循环里
  不可能漏进一个变更）；`execute_write()` 校验批准凭据与方案严格绑定。
- **fail closed 贯穿始终**：未登记的工具默认当写操作；provider 声明写工具却没有
  dry-run 直接拒绝装配；远程 MCP 工具默认一个都不导入。
- **审批卡片带真东西**：影响面分析（副本数 / 单点 / PVC / PDB / 上游依赖）+
  服务端 dry-run 结果 + 回滚方式，而不是一句"模型建议重启"。
- **审计链可检出篡改**：追加写 + 哈希链，跨进程文件锁（Web 与 CLI 同时写不断链）。

**第二段：Agent 工程**

- 手写 function-calling 循环（**不引 LangChain**），精确控制"哪一步能碰集群"。
- **上下文工程**：工具调用不消耗轮次预算（不惩罚多取证），但配了**退化循环护栏**
  ——同一工具连续落空或同参数重复就注入系统消息点破它。
- **语义记忆**：结构化案例库（症状签名 + Jaccard 相似度），**只吸收执行后复查确认
  有效的修复**；刻意不用向量库——K8s 症状是可确定性计算的，降维成 embedding
  反而丢失可解释性与可审计性。
- **MCP 双向**：server 端手写 JSON-RPC over stdio；client 端接外部 server，
  白名单机制 + 子进程生命周期管理。

## 四、这个项目最值得讲的三件事

面试官区分"做过"和"想过"，看的就是这种地方。**三个都是真实踩过的坑。**

### 1. 单次采样是自欺 —— 5 轮评测才敢报一个数

第一轮跑完是 11/15。直接报"73%"会把四个**抽样波动**的场景冤枉成能力问题；
但同一批数据换个角度也能报出"93%"。**两个数字都是真的，两个都是误导。**

于是我重跑失败项、再跑全量，前后 **5 轮共 75 次场景运行**，才把两类失败分开：

- **波动**（`image` / `unhealthy` / `oom` / `inject`）：重跑就过，是采样噪声
- **可复现短板**（`probe` / `crash` / `cordon`）：几乎每次都失败

**基线稳定在 10~11/15，三个真短板。**

然后我逐个修掉了它们，**现在是 14/15（93%）**——而且每一轮都有前后对照：

| 轮次 | 通过 | 关键动作 |
|---|---|---|
| run1~5 | 10~11/15 | 方差分析，把波动和缺陷分开 |
| run6 | 10/15 | 加了个独立工具 → **15 个场景调用 0 次** |
| run7 | 12/15 | 改成把信息**塞进模型本来就会调的工具** |
| run8 | 12/15 | 用 runbook 修回被钝提示词弄坏的场景 |
| run9 | **14/15** | 让症状签名能区分两类故障 → 后两个也通过 |

**面试时讲这条链，比报任何一个数字都有说服力。**

### 2. 护栏会反噬 —— 修正一个行为，制造了一个事故

为了修"模型把方案写在聊天里、不提卡片"，我加了一条结构性纠正（nudge）。结果
`probe` 场景翻车：模型**第一段已经正确地说**"不建议现在做滚动重启"，被 nudge
催着"提点东西"之后，**把自己上一段刚否掉的陷阱动作提了出来**。

> 为了让模型"做点什么"而施加的压力，如果不管住方向，会变成新的事故来源。

修完重跑验证，避坑率从 93% 回到 100%。**约束模型行为的手段本身也需要被评测。**

### 3. 抽象层只接了一半 —— 三层验证全都没抓到

我给 provider 加了只读工具（Prometheus），单元测试过、评测过、手工也"验证"过。
实际上**那些工具在会话里根本执行不了**，一调用就报"未登记"：

- **根因**：session 用模块级的 `is_mutating()` 判断读写，它对**未登记的工具默认
  返回 True**（刻意的 fail-closed）。引入注册表之后，provider 的只读工具被误判成写操作。
- **为什么三层都没抓到**：单测测的是注册表和 `run_readonly()`，**没测 session 路由**；
  评测跑的时候**不装配 provider**；手工验证只看了工具**名字**出现在列表里，
  **没看 `ok` 字段**。

**教训**：fail-closed 是对的，但"未登记 → 当写操作"这条规则在引入注册表之后
必须由注册表回答。**加抽象层时最容易漏的，就是"原来那个判断在新世界里还成不成立"。**

## 五、面试必答清单（能答 12 条再往上写）

### 基础题（答不上就别写这个项目）

1. **为什么要人工审批？** —— 只读自动执行（不需要许可），写操作必须人点卡片。
   LLM 判断不可靠，但它**能表达的只是一组受 schema 约束的参数**，这是切断
   "模型幻觉 → 生产事故"最短路径的地方。
2. **dry-run 是什么、为什么执行前要重跑？** —— K8s 原生 `dry_run=All`，服务端校验
   且不改状态。批准时重跑是因为**卡片上的结论是生成那一刻的快照**，集群可能早变了
   （TOCTOU）。
3. **fail closed 具体指什么？** —— 未登记的工具默认当写操作；provider 写工具没有
   dry-run 就拒绝装配；MCP 远程工具默认一个都不导入。
4. **审计链怎么防篡改？** —— 追加写 + 每条记录带前一条的哈希。跨进程必须加文件锁，
   否则 Web 与 CLI 各自持有 seq 计数器、交叉写入会让链断裂（真实踩过）。

### 进阶题（决定你是"做过"还是"想过"）

5. **为什么不用 LangChain / LangGraph？** —— 这个 Agent 的核心是**安全边界**，
   不是编排复杂度。手写循环让我能精确控制哪一步能碰集群；引入框架会把安全边界
   埋进别人的抽象里。运行时依赖只有 2 个，**"它到底能碰什么"可以被完整读一遍**。
6. **为什么不用向量库做记忆？** —— K8s 症状是可**确定性计算**的（重启次数、退出码、
   就绪状态），降维成 embedding 反而丢失可解释性。结构化案例库只吸收**执行后复查
   确认有效**的修复。
7. **评测为什么不用 LLM 当裁判？** —— "另一个模型觉得它对"不是可信证据。判据全
   确定性、可复算、换裁判模型不会变分。代价是覆盖面窄，我承认样本量小。
8. **讲一次你用评测定位并修掉问题的完整过程。** —— 见第四节那条链。关键是三次转向：
   ① 发现三个稳定失败，**归因到同一个盲区**（模型不把症状和最近变更联系起来）；
   ② 加了个独立工具去补这个信息，**跑完发现 15 个场景调用 0 次**——于是明白
   **加工具 ≠ 模型会用**，改成把信息塞进它本来就必看的 `get_workload`；
   ③ 剩下两个场景加 runbook 时发现**症状签名完全相同**（一个要 uncordon、
   一个要"什么都别做"），于是先改 `symptom_tokens()` 让签名能区分，再写 runbook。
   **每一步都有前后对照的评测数据，不是"改完感觉好了"。**
9. **怎么判断是"模型不行"还是"护栏不行"？** —— 看结论文本里模型是**不知道**还是
   **知道但没做**。`cordon` 当时明确列出了"节点 cordon-drain"在自己的工具集里，
   却仍然说"硬套现有工具解决不了"——这是**知识问题**，加工具没用，得加 runbook。
   分清这两类之后，两个场景就都修好了。
10. **prompt injection 防了几层？** —— 三层：① **结构上写不动**（即使模型被说服，
    也只能"提出"，必须人点卡片）；② 围栏化 + 加权计分；③ 让人看见（事件 + 审计 +
    红色告警卡）。刻意**不删改原文**——那是证据。

### 送命题（答不上来会被认为简历造假）

11. **和 HolmesGPT 比呢？** —— 这个赛道最直接的对手（CNCF Sandbox、3.4k star、
    150+ evals）。**我把安全性押在"结构"，它押在"人"**：它的写工具是 catch-all 的
    `run_kubectl_command`（任意 kubectl），RBAC 是含 `pods/exec`、`nodes: patch` 的
    ClusterRole；我用能力枚举 + fail-closed。**它评测规模比我大一个数量级、
    工具生态 40+ 集成，这两条我承认落后。**
12. **"8 个项目里 0 个做注入防御"怎么来的？** —— 逐个项目读文档和源码得出的
    （`docs/竞品对比.md`），star 数用 GitHub API 实测复核过。**有 4 项我标了
    `unknown` 而不是"没有"**——那是没有依据，不是不存在。
13. **这个项目有多少是抄的？** —— 沙箱拓扑、评测剧本、安全边界都是自己设计的。
    同类项目调研是**先做产品、后做对比**，用来确认自己的差异点是否成立。

## 六、客观定位

**强在哪**（都可验证）

- **安全架构的结构性强于** 8 个同类项目里的多数：写操作有强制审批的只有 2 个，
  做注入防御的是 **0 个**；而默认不安全（审批默认关 / 写默认开）的有 2 个。
- **评测方法论**比多数个人项目扎实：确定性判据 + 重复采样 + 主动报告短板。
- **手写深度**：HTTP 服务、认证、MCP 双端、JSON-RPC、容器化，运行时依赖只有 2 个。

**弱在哪**（主动说，别等被问）

- **工具生态差距**：HolmesGPT 有 40+ 集成，我只有 K8s + Prometheus + Loki + MCP。
- **评测规模差距**：人家 150+ evals 且进 CI，我 15 个剧本、手工跑。
- **单模型绑定**：只对接了 DeepSeek（OpenAI 兼容接口，但没验证过别家）。
- **社区为零**：个人仓库 vs CNCF Sandbox。
- **唯一没过的 `crash` 是波动**——但样本量只有 9 轮，**不能声称它一定没问题**。

**这算什么水平**：不是"又一个 AI 运维助手"（那样会被 8.2k star 的 k8sgpt 直接比下去），
而是**一个把"Agent 的安全执行"讲清楚并做扎实的项目**。定位就卖这个。

## 八、关键词缺口（重要，真实风险）

国内 Agent 岗 JD 高频词：**Python、LangChain/LangGraph、RAG、向量数据库、
Tool Calling、MCP、Docker/K8s**。

你有 **Python ✅ Tool Calling ✅ MCP（双向）✅ Docker/K8s ✅**，
缺 **LangChain/LangGraph ❌ RAG ❌ 向量库 ❌**。

简历初筛靠关键词匹配，这三项缺失**可能让你过不了初筛**。三条应对：

1. 技术栈行写 **Hand-rolled agent loop / Function Calling / MCP（server + client）**，
   把"懂原理"放在显眼处。
2. 面试主动把"不用框架"讲成**判断力**（见进阶题 5）——但**前提是你真想清楚了**。
3. **投入产出比最高的一步**：花两三天用 LangGraph 把这个循环重写一遍做对比，
   简历上写"对比了手写循环与 LangGraph 两种实现"。既补关键词，又直接回答了
   "你为什么不用框架"——而且你**真的**试过了，不是背的答案。

## 九、最后一句

这个项目最值钱的不是那上万行代码，是**一套能自我证伪的方法**：
15 个真故障剧本、多轮重复采样、主动区分波动与缺陷、改完必须重跑验证。

它已经跑完了一个完整闭环：**发现短板 → 归因 → 修 → 用同一套评测证明修好了**
（10~11/15 → **14/15**），而且中间有两次假设被评测直接证伪
（"加工具没用"、"runbook 写不了"）。

**面试时不要背数字，讲那条链。** 数字谁都能编，**被证伪过又改对的假设编不出来**。
