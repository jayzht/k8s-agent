# 归档：描述"已删除的规则层"的历史文档

这里的文档写于 **v0.1 架构**，那一版的核心是一套分层风险矩阵：

- 工具按 T0/T1/T2/T3 分级
- `config/policy.yaml` 配置熔断规则（影响面上限、冷却期、保护标签、命名空间白名单）
- 单轮诊断 + 规则引擎匹配已知故障模式
- 37 条自建评测用例 + fuzz 生成的盲区报告

**v0.2 把这套东西整个删掉了**，理由见根目录 README 的「规则层去哪了」一节。
结论是：真正需要的安全属性只有一条——"只读自动执行、写入必须人工确认"——
它在代码里是一个布尔值就够，不需要一个可配置的规则引擎去表达。
规则引擎的额外复杂度并没有换来对应的安全性，反而让"为什么这个动作被拦了"
变成一个要去查 YAML 才能回答的问题。

保留这些文档是因为其中的**调研过程和踩坑记录仍然有价值**
（比如 ITBench 真实数据评测的结论、规则引擎假阳性/漏报的具体案例），
但它们描述的**代码已经不在了**，命令也跑不通。

| 文档 | 内容 | 现状 |
|---|---|---|
| `PRD-v0.1.md` | 产品定义与 T0–T3 分级设计 | 设计已废弃，问题定义仍可参考 |
| `real-data-eval.md` | ITBench-Lite 真实数据评测 | 评测代码（`evals.py`/`itbench.py`）已删除 |
| `rule-blindspots.md` | 规则引擎盲区报告 | 规则引擎本身已删除 |

需要了解当前架构，请读根目录的 [`README.md`](../../README.md)。
