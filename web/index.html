用一句话描述问题

Agent 会先把这句话解析成结构化查询，再走标准诊断链路。 解析不出目标时它会直说，而不是猜一个。

或直接选择工作负载

    ① 注入一个故障

    模拟"某个开发推了一次坏变更"。注入后点工作负载诊断。

    ③ 试试越界请求

    看 Agent 如何拒绝危险动作——即使你强行批准也执行不了。

    选择一个工作负载开始诊断

    Agent 会读取 Pod 状态、事件、日志与 PDB，给出带证据的结论与候选处置动作。

    任何写操作都必须经过人工确认，且无法被此界面绕过。

    取证过程

    证据链

    #类型对象内容

    候选处置动作

    哈希链式追加日志，任何篡改都可被检出。

      每次处置沉淀为「症状→根因→处置→结果」，越用越快。

        两步上手

        1. 左栏点一个「注入故障」按钮
          （模拟一次坏发布）
        2. 点工作负载名 → 看诊断 → 点「生成确认卡片」→ 点「确认执行」

        你在看什么

        中间诊断证据链 + 候选动作 + 确认卡片
        右栏·审计哈希链日志（可检出篡改）
        右栏·知识历次处置沉淀，越用越快
        右栏·策略当前生效的 Tier 白名单与熔断规则

        三个值得看的点

        ① 确认卡片：影响面、dry-run、回滚路径、熔断检查一屏说清——这是产品主体。

        ② 受保护负载：点 billing-core（黄色左边框）诊断，方案会被「保护标签」熔断拦下。

        ③ 越界被拒：左栏第 ③ 组按钮，看 Agent 拒绝并给替代方案。
